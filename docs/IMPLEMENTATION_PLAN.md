# IMPLEMENTATION_PLAN · 分阶段实现计划

原则：**每个阶段结束时项目都能编译、能装、能跑**，并且能拿出一个你可以自己验证的东西（真机截图或一段可点的流程）。不铺开写全部页面，先把一条垂直路径打通。

**2026-08-06 更新**：六个问题全部裁决完毕。提醒通知不做（原阶段 9 删除）、休息日不做、**备份导出改为进第一版**（新增阶段 9）、向导字段与底栏样式按推荐默认执行。手机确定为一加 13 / Android 16，compileSdk 与 targetSdk 定 36。现在一共 11 个阶段。

---

## 阶段 0 · 环境与工程骨架

**目标** 在 `android/` 下建起一个能编译出 APK、能装到你手机上的空壳。

**范围**
- 环境：JDK 17 + Android SDK 已在本机；补装 platform android-36 与 build-tools 36；首次构建下载 Gradle 与依赖约 1 GB
- `android/` Gradle 工程：Kotlin + Compose + version catalog
- 包名 `com.zyj.ritual`，应用名「夜读」（可改）
- minSdk 26 / compileSdk 36 / targetSdk 36
- 一个显示"Hello"的 Activity

**验收** 手机上能装上、能打开、不闪退。
**测试** `./gradlew assembleDebug` 通过；真机安装一次。

## 阶段 1 · 设计系统（Theme）

**目标** 把 `design-tokens.json` 变成代码，之后所有页面只用这些 token，不出现裸色值。

**范围**
- `theme/Color.kt`（15 个颜色）、`Type.kt`（13 档字体）、`Dimens.kt`（间距/圆角/尺寸）、`Motion.kt`（5 组动效参数）、`RitualTheme.kt`
- Manrope + IBM Plex Mono 拉丁子集入 `res/font/`
- edge-to-edge + 深色状态栏图标 + WindowInsets
- 一个 `TokenGalleryScreen`（只在 debug 构建里），把颜色、字号、间距全画出来

**验收** 真机截 TokenGallery 与 `设计系统.dc.html` 并排比对，颜色和字号一致；中文字重差异可接受（这是决定要不要子集化中文字体的时点）。
**测试** 编译通过 + 一张真机截图给你看。

## 阶段 2 · 领域层与核心算法（★ 最重要的一阶段）

**目标** 把所有算术写完并测透，此时还没有界面。这是整个 App 唯一容易出错的地方，先把它钉死。

**范围**
- `domain/model/`：TaskRecord、Plan、DayStatus 等
- `PlanCalendar`（R1–R5）、`ProgressCalculator`（R6–R10）、`CreditCalculator`（R11–R18）、`DayStatusResolver`（R26–R30）、`TodayCopyResolver`（R31–R38）
- `core/time/BeijingClock` + 可注入 Clock

**验收** `REQUIREMENTS.md` 第 5 节的每一条规则都有对应测试且全绿；用原型的种子数据（起点 12 篇、8 月 5 日开始、第 12 篇已在 8 月 3–4 日完成）跑一遍，算出来的数字与原型一致。
**测试** `./gradlew test`，domain 层覆盖率 ≥ 80%，`TimezoneTest` 必过。

## 阶段 3 · 本地存储

**目标** 数据能存下来、杀进程不丢。

**范围**
- Room：`task_record` + `history_event` 两表、DAO、数据库
- DataStore：`PlanStore`
- `StudyRepository`：唯一数据入口，暴露 `Flow<List<TaskRecord>>`、`Flow<Plan>`、`todayFlow`
- 起点 IMPORTED 记录的生成/增删逻辑（`TECHNICAL_PLAN.md` 3.2）

**验收** 用一个临时的调试按钮写入若干记录，杀进程重开数据还在。
**测试** `./gradlew test connectedAndroidTest`：DAO 增删查、幂等写入、IMPORTED 记录随起点篇数变化、Repository 的 Flow 发射正确。

## 阶段 4 · 首次设置向导 + 计划生成

**目标** 第一条完整的垂直路径：装好 App → 走向导 → 落库 → 进一个还很朴素的 today。

**范围**
- `SetupScreen` + `SetupViewModel`，按 Q3 的结论决定暴露哪些字段
- 实时预览（剩余篇数、基础计划天数、预计完成日）
- 保存 Plan + 生成 IMPORTED 记录
- `startDestination` 判定（含 splash 等待 DataStore 首读）

**验收** 首次打开进向导；设成"已学完 12 / 2 天一篇 / 今天开始"，保存后进 today，能看到 `72 / 252` 和 `28.57%`（此时 today 可以还很粗糙）。杀进程重开直接进 today 不再进向导。
**测试** 单元测试覆盖向导的预览计算；UI 测试走一遍"加减起点 → 保存 → 进 today"。

## 阶段 5 · 今日学习页 + 文章详情

**目标** 每天真正会用的那一屏，做到设计稿水准。

**范围**
- `ProgressRing`（Canvas 两段弧 + 480ms 动画）、`SegmentedTicks`、`TaskRow` 全 5 态、`CreditCard` 三态、`PrimaryPill`
- `TodayScreen`：日期行、标题（R31–R34）、主区、额度卡、两组任务、底部主按钮（R35–R38）、底部导航
- `ArticleScreen`
- 勾选 220ms 动画 + 轻触觉；撤销确认弹窗（文案要写出回退后的两个数字）
- 跨天自动刷新接进来

**验收**
1. 勾一项，环扫过、数字变、主按钮换成下一项；
2. 连勾 6 项，完整篇数 12→13，主按钮变"开始第 14 篇"，额度卡变 +1 天；
3. 点已完成项，弹窗文案里的回退数字与撤销后的实际数字一致；
4. 真机截图与 `dev/prototype-screens/01-today.png` 视觉一致。

**测试** `test` + UI 测试（勾选→数字变化、撤销弹窗文案）。

## 阶段 6 · 月历 + 日期面板

**目标** 把"哪天做了、哪天欠着"看出来，并且能就地补打卡。

**范围**
- `CalendarCell` 9 态、月格布局（412dp/54dp、360dp/48dp）、图例
- `HorizontalPager` 切月（范围 = 计划开始月前 1 月 ~ 预计完成月后 3 月）+ 箭头
- 摘要三格
- `DaySheet`：原计划、状态标签、当天 3 项可勾可撤销、随状态变化的说明、两个按钮；**计划开始前的空态要隐藏"全部标记完成"**（原型的 bug，见 `DESIGN_AUDIT.md` 7.2.3）
- 返回键：先收面板

**验收** 造出 9 种日格状态各一个并截图比对设计系统第 06 节；在过去某天的面板里补记一项，回首页看到缺额减少、历史多一条"补记"。
**测试** `DayStatusResolverTest` 已在阶段 2 完成；本阶段加 UI 测试"点日格→开面板→勾一项→关面板→格子状态变化"。

## 阶段 7 · 进度页 + 历史记录

**目标** 回答"我走到哪了、什么时候能读完"。

**范围**
- 60sp 百分比、双段进度条、42 格矩阵、ETA 卡（基础计划完成日 / 按当前速度预计 / 解释文案）
- 历史记录列表（过滤 IMPORTED）+ 空态
- 完成页 `DoneScreen`

**验收** 数字与 today 页一致；历史里能看到"提前/完成/补记/撤销/排期"五种标签；把 252 项全部完成后出现完成页，撤销一项后退回 today。
**测试** UI 测试：历史空态、完成页出现条件。

## 阶段 8 · 超前、逾期与重新排期

**目标** 把三条"不按计划走"的路径闭环。

**范围**
- 缺额暗铜卡 + 「优先补上」（按最早缺口顺序，R16/R23）
- 重新排期：确认弹窗（区分领先/缺额两种文案）+ 执行（R39–R42）
- 设置页：改节奏、重进向导、撤销整篇及其确认弹窗
- 撤销整篇后的进度回退

**验收**
1. 空过 2 天后首页出现"缺 6 项 · 最早缺口 08.07"，日期指向真实的第一个没做完的计划日（不是估算）；
2. 点「优先补上」按最早缺口补齐，缺额归零；
3. 重排后：计划轴从今天起、额度归零、**历史记录的时间戳一条没变**；
4. 撤销整篇后完整篇数和总项数同时回退。

**测试** `RescheduleTest` + UI 测试走完整逾期→补上→重排流程。

## 阶段 9 · 备份导出与恢复

**目标** 换手机、误删、重装都不丢数据，而且 App 依然零权限。

**范围**
- `kotlinx.serialization` + 备份 JSON 结构（`TECHNICAL_PLAN.md` 第 7 节）
- 导出：系统文件选择器（`CreateDocument`），默认文件名带日期时间
- 导入：`OpenDocument` → 格式版本与结构校验 → 二次确认弹窗（写明会覆盖）→ 事务内整库替换 → 全量重算
- 设置页补两行「导出备份」「从备份恢复」，用现有卡片样式

**验收** 导出一份 → 在系统设置里清掉 App 数据 → 重开走向导 → 从备份恢复 → 所有数字、历史记录、时间戳与导出前完全一致。喂一个残缺 JSON 进去，报错且现有数据不受影响。
**测试** 单元测试：序列化往返一致、版本号不认识时拒绝、结构残缺时拒绝；手动验证真机上的文件选择器。

## 阶段 10 · 适配、无障碍与收尾

**目标** 换个手机、放大字体、开 TalkBack 也不崩。

**范围**
- 360dp 窄屏、系统字体放大 130% / 200%
- TalkBack 朗读文案（任务行要读出"未完成/已完成 + 任务名"）
- App 图标与启动画面
- 全局检查：无裸色值、无 `LocalDate.now()` 无参调用、无遗留调试入口（原型的 DEMO 按钮绝不能进包）、`AndroidManifest.xml` 里没有任何权限声明

**验收** 三种字体缩放下各截一屏无截断；TalkBack 能走完一次打卡。
**测试** 全量 `test` + `connectedAndroidTest` 绿。
