### 7.2 原型自身的逻辑瑕疵（我在跑的时候发现的，不是设计错误，是原型简化）

1. **首页标题会串台**。标题模板是「今天开始第 {当前篇} 篇的第 {计划相位} 天」，其中"当前篇"取自实际完成情况、"第几天"取自计划公式。空过 2 天造成逾期后（截图 `10-today-overdue.png`），日历上 8 月 9 日的计划是第 14 篇，标题却写"今天开始第 13 篇的第 1 天"。实现时要给标题定一条明确规则（我在 `REQUIREMENTS.md` 5.6 给了）。
2. **最早缺口日期是估出来的**。原型用 `今天 − ceil(缺额/3)` 反推日期，不是真的去找"第一个没做完的计划日"。逾期跨越多篇时会指错日子。实现要改成正向扫描。
3. **计划开始前的日期面板仍显示"全部标记完成"按钮**，点了没有任何反应（截图 `04-day-sheet.png`）。这个按钮在空态应该隐藏或禁用。
4. **原型的"底部导航"没有用交付的图标**。`assets/icons/tab-*.svg` 四个图标躺在那儿，原型的底栏画的却是"5dp 金点 + 文字"。两者只能选一个——设计系统第 09 节把图标列为正式资产，我倾向底栏用图标 + 文字、选中态保留金色，但这属于视觉决定，见问题清单 Q5。
5. **"已学完 12 篇"在原型里是一个不产生记录的基数**（`baseArts`），撤销整篇时靠 `baseArts − 1` 兜底。这在真实数据库里会变成两种"已完成"（有记录的 / 没记录的），是实现上必须先处理干净的一处，我在 `TECHNICAL_PLAN.md` 3.2 给了方案。
6. **交接说明和视觉探索对 360dp 机型的日历格高说法不一致**：交接说明写"压到 48dp"，视觉探索写"压到 44dp"。按交接说明（更新的那份）取 48dp。

## 8. 原生安卓实现的潜在问题

按风险从高到低：

1. **中文字体体积**。Noto Sans SC 单个字重完整包约 8–10 MB，三个字重打进 APK 会让安装包直接超过 25 MB。方案：中文走系统字体（国内机型的系统中文字体与思源黑体同源，观感接近），只把 Manrope 和 IBM Plex Mono 的拉丁子集打包（两者合计约 150 KB）。这样数字和时间戳的"设计感"保住了，中文正文用系统字体，视觉损失可以接受。**注意如果以后决定子集化中文字体，改文案后必须重跑子集脚本，否则手机上会静默缺字。**
2. **进度环不能用 CSS conic-gradient**。要用 Compose `Canvas` + 两段 `drawArc`（蓝弧 + 金弧）+ `StrokeCap.Round`，`animateFloatAsState` 驱动 480ms 扫过。这是有实现成本的一块，但风险可控。
3. **`java.time` 与最低版本**。`LocalDate`/`ZoneId` 需要 API 26+，或者开 core library desugaring。建议直接 minSdk 26（Android 8.0，2017 年）。
4. **"今天"跨天刷新**。App 在前台放着过了北京时间 00:00，所有派生量（今日计划、额度、逾期）必须重算。要在 ViewModel 里挂一个到下一个北京零点的定时器 + `ON_RESUME` 重算，不能只在启动时算一次。**设备时区不等于北京时间**，本机时区如果是别的地方，用设备日期会整天算错。
5. **月历的 HorizontalPager 页数**。不能无限翻，要给定范围（计划开始月的前 1 个月 到 预计完成月的后 3 个月），否则 pager 状态和"跳回今天"都不好写。
6. **底部面板 + 返回键**。Compose 的 `ModalBottomSheet` 默认会吃掉返回键收起自己，行为和设计一致，但要确认 predictive back（Android 14+）下不会出现面板和页面同时后退。
7. **动效克制**。设计明确禁用模糊、视差、常驻循环动画——这条要写进代码评审清单，避免后面顺手加了个 loading 转圈。
8. **状态只靠颜色**这一点，如果你想要更好的可用性，日历格可以给"提前完成"加一个极细的外环形状差异。属于可选增强，不改设计基调。

## 附：原型状态机（我从 `交互原型.dc.html` 的脚本里逆出来的，这是需求的事实基准）

```
计划映射   第 k 个计划日（k = 日期 − 计划开始日, k ≥ 0）
           → 篇号 = 起始篇 + floor(k / 2)，相位 = k mod 2 + 1
           → 相位 1 = 任务 1,2,3；相位 2 = 任务 4,5,6
当前篇     从"起点篇"往后第一个不满 6 项的篇
整体进度   (起点已完成项 + 新完成项) / 252，两位小数
完整篇数   6 项齐全的篇数
额度       新完成项数 − max(0, 今天 − 计划开始日) × 3     （单位：项，÷3 得天）
           > 0 领先（金）  = 0 齐平（中性）  < 0 缺额（暗铜）
预计完成日 今天 + ceil(剩余项 / 3)
基础计划日 计划开始日 + (42 − 起始篇 + 1) × 2 − 1
重新排期   计划开始日 = 今天，起始篇 = 当前篇；已完成记录与时间戳一律不动
补打卡     从最早未完成项开始按顺序填，时间戳记为实际操作时刻
```
